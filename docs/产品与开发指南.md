# AIFS 产品与开发指南

## 1. AIFS 到底是什么

**AIFS 是装在 DSH 里的 REST 计算助手插件。**

你告诉它想研究什么，它帮你拆成几个计算步骤，讨论每一步用什么泛函和基组，再生成 REST 的 `.in` 输入文件。这里的“输入卡”就是这个文件：REST 读取它，才知道要算什么。

目前，AIFS 帮你准备计算。**实际运行 REST 仍由你完成。**

向别人介绍时可以这样说：

> 我做了一个依托 DSH 的分子计算助手。用户说出研究目标，它帮助规划步骤、选择方法，并生成每一步的 REST 输入文件。计划、选择理由和文件都能保存，后面可以接着做。

## 2. 用一个例子看懂怎么用

你说：“我想先优化水分子的结构，再算它的电子能。”

1. **助手整理成两步。** 第一步找合适的分子结构，第二步用优化后的结构算电子能。
2. **你确认计算设置。** 提供坐标、坐标单位、电荷和自旋多重度。助手给出方法建议，你分别选优化和单点能的泛函、基组；已经说清楚的设置不用重复选。
3. **AIFS 保存计划，给你优化输入文件。** 单点能需要优化结果，此时先等待，不拿初始坐标代替。
4. **你运行优化，把结果发回来。** 提供优化后的坐标，并说明这些坐标的单位。
5. **AIFS 更新计划，给你单点能输入文件。** 优化和单点能可以用不同的泛函、基组。
6. **以后还能继续。** 重开会话后，可以让助手找回已保存的计划。修改方法会留下旧版本，旧文件也保留，能查到当时用了什么设置。

流程就是：

**提出需求 → 确认设置 → 保存计划 → 拿到当前能用的文件 → 运行 REST → 补回结果 → 拿到后续文件。**

## 3. 现在已经能做什么

- **拆计算步骤并保存。** 记录每一步要做什么、要等哪一步、还缺什么信息。
- **分别选方法。** 优化、单点能、频率可以分别选泛函和基组。需要做能量相减时，参与相减的最终能量计算应使用一致的方法和设置。
- **说明建议的依据。** 用模型知识、网页和本地文献记录讨论方法，保存理由和引用。找不到可靠文献时也可以给初步建议，但要说明依据不足。
- **检查能否出文件。** 没有坐标单位、没选基组，或者所选设置目前不能生成时，会说明缺什么。不能出现“A 等 B、B 又等 A”的步骤安排。
- **生成和检查 `.in`。** 写好文件后，再检查格式和已接入的 REST 参数规则。可下载，也可通过 DSH 文件工具导出或在聊天里查看正文。
- **保留修改记录。** 能找到以前的计划和文件，知道每张卡对应哪一步、哪一版设置。
- **自动启动后台程序。** 桌面用户启用插件即可；状态页显示是否可用，失败时能看原因和重试。

文件检查通过，表示它符合 AIFS 当前掌握的输入规则。计算能否收敛、方法是否足够准确，还要看实际 REST 运行结果。

## 4. REST 的功能覆盖全了吗

**还没有全覆盖。** 当前能为下列功能准备输入，但具体泛函、电子态和参数组合有条件：

| 想做的事 | 当前接入的计算类型 |
| --- | --- |
| 算能量、找稳定结构 | 单点能、几何优化、力；包含 TPSS、部分 ωB97 变体和 XYG3／XYG7 等方法 |
| 补振动和实验对比所需的修正 | Hessian、振动频率、ZPE（零点振动能）和热化学设置 |
| 看电荷分布相关性质 | 数值偶极、电多极矩 |
| 研究电子激发 | TDDFT／TDA、频域响应、FEAST、PySOC 导出及部分激发态力 |
| 研究反应路径 | 过渡态、IRC（从过渡态向两侧追踪反应路径）、固定原子等优化设置 |
| 做部分周期重构分析 | 一维／二维 RRS-PBC；它是在有限团簇结果上做重构，不是直接做周期 SCF |

还没完整接入的有：分子动力学（MD／AIMD）、QM-MM／pure-MM、GW／BSE、analdrv 密度导出、三维 RRS-PBC、复杂激发态优化和梯度、任意 LibXC／自定义泛函表达式。AIFS 也不负责准备计算机器上的基组、ECP 和其他外部文件。

完整条件见 [REST 能力范围](../packaging/rest-coverage.md)。开发者增加功能时，要先确认对应 REST 版本实际接受哪些输入，不能只看到某个泛函名字就认为所有性质都能算。

与实验比较时，先弄清楚实验测的是什么。例如，含 ZPE 的绝热脱离能需要两个物种各自的零点能修正，不是固定减去一个 ZPE；能量差也不等于完整光谱。AIFS 可以保存所需步骤和公式，**目前不会自动读取 REST 输出或替你计算这些公式。**

## 5. DSH、模型和 AIFS 分别干什么

| 部分 | 用白话解释 |
| --- | --- |
| DSH | 你使用的桌面软件。提供聊天、模型设置、会话记录、选择面板，以及网页和文件工具 |
| 模型 | 理解你的问题，提出步骤，比较方法，组织回复。你在 DSH 里选择官方或自定义模型 |
| AIFS Skill | 给模型看的专业指南：什么时候追问、怎么拆步骤、哪些物理量容易混淆 |
| AIFS 工具 | 模型调用的具体动作，例如“保存计划”“生成这一步的输入文件” |
| AIFS 后端 | 插件附带的 Python 程序。接收工具请求，检查参数，生成文件，保存记录 |
| 数据库 | 本机保存计划、方法选择和卡片的地方；换插件版本时，数据仍单独保留 |

**Skill 负责指导模型，后端负责执行检查。** 例如，Skill 提醒模型“单点能要等优化结果”；后端收到缺少结果坐标的任务，也会阻止出卡。

模型密钥只在 DSH 设置。AIFS 后端自动在本机启动，插件通过本机 HTTP 与它通信；不需要普通用户手动开 localhost 服务。

## 6. 安装包、源码、数据是什么关系

- **源码仓库**：开发者修改的 Python、TypeScript 和 Markdown 文件。
- **安装包 `.tgz`**：把插件、Skill 和能直接运行的后端装在一起。用户直接添加到 DSH，不用解压，也不用安装 Python 或 Node。
- **DSH 安装副本**：DSH 安装后使用的那份程序。修改源码不会自动更新这份副本，要重新打包并升级。
- **用户数据**：保存到 `$DSH_HOME/aifs/`，即 DSH 数据目录里的 `aifs` 文件夹，通常是 `~/.dsh/aifs/`。它与安装程序分开放，升级和卸载插件保留数据。

目前有 Mac arm64 和 Windows x64 测试包；Intel Mac 暂无已验收包。安装步骤见 [README](../README.md)，数据搬家见 [安装说明](../packaging/README.md)。旧 Web 方式是早期开发入口，当前桌面使用不需要它。

## 7. 接手开发：工具和接口怎么看

**工具是给模型调用的，接口是给插件调用后端的。**

例如，模型调用 `create_aifs_plan`，插件把计划发送到后端的 `POST /v1/plans`；后端检查并保存后，返回计划编号和各步状态。`POST` 表示提交内容，`GET` 表示读取，`PUT` 表示更新。

当前共有十个 AIFS 工具：

| 工具名 | 给它什么，它做什么 |
| --- | --- |
| `get_rest_capabilities` | 指定想查的功能，返回当前能生成哪些输入、有哪些限制 |
| `retrieve_functional_evidence` | 给检索问题，返回本地已收录的文献记录；网页搜索由 DSH 提供 |
| `create_aifs_plan` | 给完整计划，检查并保存，返回各步状态 |
| `revise_aifs_plan` | 给计划编号、当前版本和修改后的完整计划，保存新版本 |
| `list_aifs_plans` | 查已保存的计划，返回列表 |
| `get_aifs_plan` | 给计划编号，读取最新或指定历史版本 |
| `generate_aifs_task_card` | 给计划和任务编号，为符合条件的这一步生成、检查并保存 `.in` |
| `get_aifs_card` | 给计划和卡片编号，读取已保存的正文、来源和当前下载地址 |
| `generate_rest_input` | 直接给一组计算参数，生成单张输入卡；不建立多步计划 |
| `validate_rest_input` | 给一张输入卡的正文，检查格式和参数规则 |

用户的多步需求通常走“创建计划 → 逐任务出卡”。直接生成单卡是另一个入口，不会自动拥有计划历史。

详细接口路径见 [后端 API 表](../backend/README.md#api)，工具接入方式见 [插件说明](../dsh-plugin-aifs/README.md)。

### 新需求来了，改哪里

| 需求 | 从这里开始 |
| --- | --- |
| 新的任务拆分方式，例如新的实验对比路线 | [Skill](../skills/aifs-molecular-planning/SKILL.md)：补充按目标判断的指南和例子 |
| REST 已支持，但 AIFS 还不能生成某种输入 | [capabilities.py](../backend/src/aifs/rest/capabilities.py) 说明参数和限制；[renderer.py](../backend/src/aifs/rest/renderer.py) 写文件；[validator.py](../backend/src/aifs/rest/validator.py) 检查文件。泛函名单在 [catalogs.py](../backend/src/aifs/rest/catalogs.py) |
| 计划需要保存一个新参数 | [workflow_models.py](../backend/src/aifs/workflow_models.py) 定义字段；[workflow_store.py](../backend/src/aifs/workflow_store.py) 负责保存和读取 |
| 新增一个工具或后端接口 | [tools.ts](../dsh-plugin-aifs/src/tools.ts) 注册工具，[client.ts](../dsh-plugin-aifs/src/client.ts) 发请求，[api.py](../backend/src/aifs/api.py) 接收请求 |
| 回复难懂、问题问得不合适 | 插件 [index.ts](../dsh-plugin-aifs/src/index.ts) 的提示词和 Skill；工具字段的解释在 [schema-descriptions.ts](../dsh-plugin-aifs/src/schema-descriptions.ts) |
| 后端启动或状态页有问题 | 插件 `src/desktop/` |

Python 负责规则、文件和数据；TypeScript 负责接入 DSH；Markdown 写说明和 Skill。

修改参数字段后，要运行生成命令，让插件使用同一份字段定义。否则可能出现后端要求一个字段、插件却没传的错误。旧记录的格式改变时，还要在 [workflow_schema.py](../backend/src/aifs/workflow_schema.py) 写兼容处理；升级前会备份，失败会撤销本次升级，原卡片正文不改。

开发使用 Python 3.11、Node 22。具体命令见 [开发与检查](../scripts/README.md#接口与任务维护)。改完后，检查正常输入、缺参数、不能支持的组合、旧计划读取和文件下载；测试通过再打包。GitHub 会自动检查代码，并在 Windows 机器上构建 Windows 包。

## 8. 已验证到哪一步

Mac 和 Windows 打包后的后端已经通过程序检查，包括保存计划、修订、下载一致、重启找回和退出清理。插件也已用 DSH 0.2.0-rc.2 桌面服务及 0.2.1-alpha.1 源码服务进行程序检查。

Windows 客户端实际安装、完整模型对话和 REST 数值计算仍需分别验收。程序检查通过，不能代表所有模型都会给出正确的科学建议。真实对话检查步骤见 [桌面走查](../packaging/local-acceptance.md)。

## 9. 开发轨迹：最初版本与 15 轮迭代

### 最初版本

最初用 DSH 的 Web 页面聊天，后端需要手动启动。先完成泛函与文献讨论，再加入保存多步计划、检查缺项和生成输入卡。知识图谱还没完整建好，因此借助 DSH 的网页工具补充来源。

DSH 有桌面版后，0.1.0 把插件、Skill 和后端打成 Mac 安装包。用户启用插件就能自动启动后端。首次安装和真实对话又暴露了导入、坐标单位、工具参数说明的问题，随后逐项修正。

### 15 轮具体做了什么

这里按 0.1.1–0.1.15 整理实际迭代，每轮包括需求讨论、修改、检查与说明更新。

| 轮次／版本 | 解决的问题与完成的工作 |
| --- | --- |
| 1 · 0.1.1 | 没查到文献也要能规划：让模型给出有理由的初步建议，说明不确定之处，等待用户确认 |
| 2 · 0.1.2 | 回复像接口报告：改为讲计算步骤、进度、文件和下一步，减少内部编号和英文状态 |
| 3 · 0.1.3 | 工具缺失时模型手写文件：补充处理指导，说明手写草稿没有经过 AIFS 保存和校验；继续查工具缺失原因 |
| 4 · 0.1.4 | 用户想点选参数、直接拿到文件：指导模型调用 DSH 选择面板，将保存的输入卡导出成文件 |
| 5 · 0.1.5 | 网页失败后不停搜索：增加停止补查的指导，保留证据缺口，继续准备已确认的方法 |
| 6 · 0.1.6 | 总推荐 PBE0：扩大方法比较，区分 REST 本身不支持与 AIFS 还没接入 |
| 7 · 0.1.7 | 想覆盖更多 REST 功能：核对官方源码，加入能力查询工具和频率、热化学、TDDFT、TS／IRC 等输入 |
| 8 · 0.1.8 | 高级性质不能只看泛函名字：补充 Hessian、多极矩、响应和部分激发态力，接入一维／二维 RRS-PBC，并检查各自限制 |
| 9 · 0.1.9 | 后端启动时模型看不到工具：改为启用就注册工具，调用时等待就绪；失败能返回原因并重试 |
| 10 · 0.1.10 | 泛函和基组合在一个问题里：改成分别选，优化和最终能量也分别选 |
| 11 · 0.1.11 | 优化方法选项太少：补充 TPSS、杂化和适用的双杂化候选，说明数值力要求和成本 |
| 12 · 0.1.12 | 实验对比缺 ZPE，Windows 也需要包：补频率与零点能步骤，完成 Windows 原生打包，修复两平台路径和换行问题 |
| 13 · 0.1.13 | 回复公式可能与计划不一致：加强 ADE、VDE、ZPE 的说明，明确模型、DSH、AIFS 各负责什么，交付两平台包 |
| 14 · 0.1.14 | 没选基组也可能出卡：审查 Skill，补后端拦截；确认基组后再生成，并增加相关测试 |
| 15 · 0.1.15 | 后续开发容易漏改接口、影响旧数据：加入字段自动同步、旧库备份升级、GitHub 检查，整理文档，采用 MIT，交付两平台测试版 |

项目发起者持续提出科学和产品需求，并用真实对话找出问题：从泛函推荐到多步输入卡，再到独立选方法、ZPE、文件交付和跨平台安装。上面的记录展示了这些需求如何落到程序、指南、测试和安装包中。当前未完成的能力仍以第 4、8 节说明为准。

**后续小更新（0.1.16）：** 补充首次解释专业名词的指导。例如第一次说 ADE 时给出中文名称和一句解释，提到 0–0 时说明它表示两边的最低振动能级；后续沿用简称。任务规则、工具和数据库格式未变。
