# AIFS 产品与开发指南

## 1. 是什么，怎么用

AIFS 是 DSH 里的 REST 计算助手。模型帮你确定计算步骤和方法，AIFS 生成并检查 `.in` 输入文件，用户运行 REST。

例如“先优化水分子，再算电子能”：

1. 提供坐标和单位，确认电荷、自旋、优化与单点的泛函和基组。
2. 模型保存两步计算，交付优化文件；单点文件等待优化结果。
3. 运行 REST，把优化坐标及其单位发回来。
4. 模型只补相关参数，AIFS 检查后生成单点文件。
5. 修改优化设置后，引用它的旧坐标被清空，后续任务重新等待。

独立计算直接出卡；想保留记录可以要求保存。安装步骤和流程图见 [README](../README.md)。

输入文件导出到工作区的 `aifs-inputs/`。独立计算各用一个目录；保存的计算按 `plan-计划编号/task-任务编号/文件.in` 分目录。后端返回路径，DSH 写入原文；修改方法会保留旧版本。已有文件内容不同时提示冲突，不覆盖。数据库记录与工作区导出文件是两份不同的数据。

## 2. 当前功能

- 生成并独立检查 REST 输入文件；缺单位、电荷、自旋或基组时不出正式卡。
- 保存任务、方法、引用、依赖和历史卡片；拒绝循环依赖。
- 优化、单点和频率分别选方法与基组；修改时只提交变化字段。
- 检查优化结果坐标的来源和单位；上游计算改变后清除失效的下游坐标。
- 旧卡仍可下载；当前任务就绪且正文一致时复用。
- 插件自动启动本机后端；状态页显示故障原因并提供重试。

**目前的结果管理范围：**程序检查“后续输入该用哪份优化坐标”。能量和 ZPE 等数值仍由用户提供、模型核对；后端没有统一保存这些结果、换算单位或计算公式的接口。保存了分析公式不表示已经算出结果。

## 3. REST 覆盖范围

| 功能 | 已接入的输入 |
| --- | --- |
| 能量与结构 | 单点、优化、力；包括 TPSS、部分 ωB97、XYG3／XYG7 等方法 |
| 振动与修正 | Hessian、频率、ZPE 和热化学设置 |
| 电学性质 | 数值偶极、电多极矩 |
| 电子激发 | TDDFT／TDA、频域响应、FEAST、PySOC 导出和部分激发态力 |
| 反应路径 | 过渡态、IRC、固定原子与优化设置 |
| 周期重构 | 一维／二维 RRS-PBC，基于有限团簇结果；不是周期 SCF |

每项都有方法、电子态和参数限制，详见 [能力清单](../packaging/rest-coverage.md)。MD、QM/MM、GW/BSE、密度导出、三维 RRS-PBC、复杂激发态导数和任意自定义泛函尚未完整接入。外部基组、ECP 和续算文件由用户准备。

输入校验不证明计算能收敛或方法足够准确。含零点能修正的 ADE 使用两个物种各自的 ZPE 差；VDE 使用同一阴离子几何上的两个电子能。能量差不等于完整光谱。

## 4. 各部分负责什么

| 部分 | 职责 |
| --- | --- |
| DSH | 模型接口与密钥、聊天记录、选择面板、网页和文件工具 |
| 模型 | 理解目标、提出步骤、解释方法、询问缺项、调用工具 |
| Skill | 给模型看的任务指南和科学注意事项 |
| TypeScript 插件 | 注册工具，将请求发给后端，展示服务状态 |
| Python 后端 | 检查参数与依赖、保存记录、生成和校验输入文件 |
| SQLite 数据库 | 保存计划版本、方法、引用和卡片 |
| REST | 实际执行科学计算 |

模型询问时优先使用 DSH 选择面板，没有面板时在聊天里问。已确认的信息保留；预选、取消或未提交不算确认。

### 产品分层与当前实现

| 层次 | 已实现 | 还缺什么 |
| --- | --- | --- |
| 科学方案：AI | 模型结合 Skill、能力查询和证据组织任务 | 科学建议和首次任务图仍需核对；不能保证每次 JSON 都合法 |
| 任务管理：AIFS | 依赖检查、优化结构来源、等待、失效、增量修订、历史读取 | 尚未统一管理能量、ZPE、波函数等结果 |
| REST 输入适配：AIFS | 能力描述、参数规则、生成器、独立校验器 | 逐项补齐 REST 功能，并做实际运行验证 |

换分子或组合现有步骤，应复用任务管理。新增 REST 参数主要改输入适配；新的结果类型或依赖可能需要扩展任务模型。REST README 不完整，接入时还要查对应源码、示例和运行结果。

## 5. 源码、安装包与数据

源码修改后要重新打包并在 DSH 升级，才能影响已安装插件。`.tgz` 包含插件、Skill 和可直接运行的后端，用户不用安装 Python 或 Node。

后端由插件启动，通过随机本机 HTTP 端口通信。数据在 `$DSH_HOME/aifs/`，默认 `~/.dsh/aifs/`，与安装目录分开。升级或卸载插件不主动删除数据；搬家方法见 [数据迁移](../packaging/README.md#迁移已有数据库)。

## 6. 工具与接口

模型调用工具，插件调用 HTTP 接口。例如 `create_aifs_plan` 对应后端 `POST /v1/plans`。

| 工具 | 用途 |
| --- | --- |
| `get_rest_capabilities` | 查询已接入的功能、参数和限制 |
| `retrieve_functional_evidence` | 检索本地已收录文献；网页搜索由 DSH 提供 |
| `generate_rest_input` | 独立计算直接生成、校验；不保存计划 |
| `validate_rest_input` | 检查已有或手动修改的输入文件 |
| `create_aifs_plan` | 首次提交完整任务图并保存 |
| `revise_aifs_plan` | 提交变化字段，保存新版本 |
| `list_aifs_plans` | 列出已保存计划 |
| `get_aifs_plan` | 读取摘要；可指定任务详情、完整内容或历史版本 |
| `generate_aifs_task_card` | 为当前就绪任务生成、校验和保存文件 |
| `get_aifs_card` | 读取历史正文、适用性和当前下载地址 |

多步流程自动保存，但首次任务图仍由模型组织。后续用 `patch` 修改；不要反复提交整份计划。补回优化结果时，在同一 patch 中更新使用该结构的任务。完整请求例子见 [局部修订计划](../backend/README.md#局部修订计划)。

卡片的 `is_current_plan_version` 表示生成版本，`is_applicable_to_current_plan` 表示是否仍能用于当前任务。判断能否使用看后者。

接口路径见 [后端 API](../backend/README.md#api)，插件接入见 [插件说明](../dsh-plugin-aifs/README.md)。

## 7. 新需求改哪里

| 要改什么 | 文件入口 |
| --- | --- |
| 科学解释、任务拆分指南 | [Skill](../skills/aifs-molecular-planning/SKILL.md) 及 references；不为每个分子写固定流程 |
| REST 参数、方法与组合 | `backend/src/aifs/rest/`：`capabilities.py`、`catalogs.py`、`renderer.py`、`validator.py` |
| 任务字段、依赖和修订 | `backend/src/aifs/workflow_models.py`、`workflow_store.py` |

| 工具与 HTTP 请求 | `dsh-plugin-aifs/src/tools.ts`、`client.ts`、`backend/src/aifs/api.py` |

| 后端启动与状态页 | `dsh-plugin-aifs/src/desktop/` |

开发使用 Python 3.11、Node 22。改 Python 接口字段后重新生成契约；检查正常出卡、缺参数、无效组合、修订和历史记录，再打包。命令见 [开发与打包](../scripts/README.md)。

## 9. 开发轨迹：最初版本与 15 轮迭代

### 最初版本

最初用 DSH 的 Web 页面聊天，后端需要手动启动。先完成泛函与文献讨论，再加入保存多步计划、检查缺项和生成输入卡。知识图谱还没完整建好，因此借助 DSH 的网页工具补充来源。

DSH 有桌面版后，0.1.0 把插件、Skill 和后端打成 Mac 安装包。用户启用插件就能自动启动后端。首次安装和真实对话又暴露了导入、坐标单位、工具参数说明的问题，随后逐项修正。

### 15 轮具体做了什么

按 0.1.1–0.1.15 记录需求、改动和验证。

| 轮次／版本 | 解决的问题与完成的工作 |
| --- | --- |
| 1 · 0.1.1 | 没查到文献也要能规划：让模型给出有理由的初步建议，说明不确定之处，等待用户确认 |
| 2 · 0.1.2 | 回复像接口报告：改为讲计算步骤、进度、文件和下一步，减少内部编号和英文状态 |
| 3 · 0.1.3 | 工具缺失时模型手写文件：补充处理指导，说明手写草稿没有经过 AIFS 保存和校验；继续查工具缺失原因 |
| 4 · 0.1.4 | 用户想点选参数、直接拿到文件：指导模型调用 DSH 选择面板，将保存的输入卡导出成文件 |
| 5 · 0.1.5 | 网页失败后不停搜索：增加停止补查的指导，保留证据缺口，继续准备已确认的方法 |
| 6 · 0.1.6 | 总推荐 PBE0：扩大方法比较，区分 REST 本身不支持与 AIFS 还没接入 |
| 7 · 0.1.7 | 想覆盖更多 REST 功能：核对官方源码，加入能力查询工具和频率、热化学、TDDFT、TS／IRC 等输入 |
| 8 · 0.1.8 | 高级性质不能只看泛函名字：补充 Hessian、多极矩、响应和部分激发态力，接入一维／二维 RRS-PBC，并检查各自限制 |
| 9 · 0.1.9 | 后端启动时模型看不到工具：改为启用就注册工具，调用时等待就绪；失败能返回原因并重试 |
| 10 · 0.1.10 | 泛函和基组合在一个问题里：改成分别选，优化和最终能量也分别选 |
| 11 · 0.1.11 | 优化方法选项太少：补充 TPSS、杂化和适用的双杂化候选，说明数值力要求和成本 |
| 12 · 0.1.12 | 实验对比缺 ZPE，Windows 也需要包：补频率与零点能步骤，完成 Windows 原生打包，修复两平台路径和换行问题 |
| 13 · 0.1.13 | 回复公式可能与计划不一致：加强 ADE、VDE、ZPE 的说明，明确模型、DSH、AIFS 各负责什么，交付两平台包 |
| 14 · 0.1.14 | 没选基组也可能出卡：审查 Skill，补后端拦截；确认基组后再生成，并增加相关测试 |
| 15 · 0.1.15 | 后续开发容易漏改接口、影响旧数据：加入字段自动同步、旧库备份升级、GitHub 检查，整理文档，采用 MIT，交付两平台测试版 |

**后续小更新（0.1.16）：** 补充首次解释专业名词的指导。例如第一次说 ADE 时给出中文名称和一句解释，提到 0–0 时说明它表示两边的最低振动能级；后续沿用简称。任务规则、工具和数据库格式未变。
