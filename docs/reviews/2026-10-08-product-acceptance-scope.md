# REST 智能体产品验收范围：任务规划、科学建议与输入卡交付

日期：2026-10-08。保留原始提问和通过标准，供真实模型验收使用；不是测试通过报告。当前执行表见 [桌面验收](../../packaging/local-acceptance.md)。

## 产品目标与范围

范围：理解目标、解释方法、确认参数、组织依赖和交付输入文件，不运行 REST。独立计算直接出卡；有前置结果或能量组合时自动保存。单步用户明确要求保存时也保存。

## 固定原始提问：WATER-01

以下原文直接用于真实模型对话，不提前把缺少的参数补进测试提问：

```text
我想计算水分子的单点电子能。坐标如下，单位是 Angstrom：
O  0.000000  0.000000  0.000000
H  0.758602  0.000000  0.504284
H -0.758602  0.000000  0.504284
我不懂电荷、自旋多重度、泛函和基组，请帮我提出方案，解释理由，需要确认的信息问我。请保存计算计划，确认后再生成 REST 输入文件。当前只准备输入，不运行计算。
```

通过标准：

- 正确识别为给定结构的单点电子能任务。不得因为用户是新手而自动增加优化、频率或热化学；若认为另一个任务有价值，应解释与原目标的关系，保留原请求范围。
- 用通俗语言解释电荷、多重度、泛函和基组；针对通常的中性基态水提出电荷 0、多重度 1 的建议并说明前提，不把建议标成用户已确认。
- 对方法和基组提供合理推荐及成本/适用性解释，允许用户接受完整推荐或分别选择；没有证据不能宣称某方法对该体系绝对最优。证据获取失败时保留条件性建议，不无限重试，也不只机械列缺项。
- 用户明确要求保存计划，因此保存包含待确认内容的计划；保存后能读回。未确认的方法或电子态保持待确认，不以默认参数提前交付正式卡。
- 用户提交确认后，使用增量修订保留已知结构与 Angstrom 单位，生成单点卡；聊天建议、实际选择、保存参数和最终正文一致。
- `.in` 正文保留给定坐标数字与原子顺序；明确写出单位，charge/spin 在正确区块，方法名/parser/基组符合目标 REST 契约。检查额外参数不能覆盖这些核心输入。
- 通过附件或可用的正文交付，文件内容与校验内容一致。明确已经准备输入、尚未运行，不给出虚构能量。

继续对话分支：

| ID | 用户动作 | 应观察到的行为 |
| --- | --- | --- |
| WATER-02 | 接受解释后的中性基态与推荐方案 | 不重复确认已接受内容，完成修订和出卡 |
| WATER-03 | 只选择泛函，尚未选基组 | 保留泛函选择，只补基组，不按默认基组出正式卡 |
| WATER-04 | 取消/未提交选择，或说“我不知道，请解释” | 保持待确认并继续解释，不把预选项当成确认 |
| WATER-05 | 生成后只更换基组 | 增量修改对应任务，其他科学参数不丢失；旧卡可追溯 |
| WATER-06 | 重开对话后要求找回 | 读回计划和已保存卡；不重新猜参数或重复生成 |
| WATER-07 | 同样结构改成“只给输入文件，不用保存计划” | 完成建议与必要确认后走直接出卡，不强制创建计划 |
| WATER-08 | 指定一个目标版本不支持的名字/组合 | 说明具体能力缺口，提出需用户接受的替代或保留待支持步骤；不静默换方法 |

## 固定原始提问：AL3-01

同样保留用户原文；不得在测试输入中暗加单重态/双重态、固定泛函或实验数值：

```text
我有一个带一个负电荷的三原子铝团簇，想知道把它的一个电子打出去需要多少能量，并跟实验光电子能谱比较。
初始坐标如下，单位是 Angstrom，还没有优化：
Al  0.000000  0.000000  0.000000
Al  2.600000  0.000000  0.000000
Al  1.300000  2.200000  0.000000
```

通过标准：

- 识别电子脱附过程 `Al3− → Al3 + e−`，保留已知阴离子电荷 −1 和 Angstrom 单位，不把它变成中性起始体系。脱附后的对应中性体系电荷为 0；两种电子态的多重度应有解释和条件，不从回归夹具复制默认基态。
- 主动用普通语言区分“电子瞬间脱离时结构不变”和“脱附前后分别允许结构松弛”的能量；首次引入 VDE/ADE 给出中文名称与短解释，不能要求新手先知道缩写才能规划。
- 针对用户要比较的实验信息澄清：阈值、某个谱带位置，还是完整谱形。未提供实验文件/来源时说明比较目标尚需确定，不编造实验数值或引用。
- 按确定的物理量组织阴离子/中性任务、结构来源、方法选择及分析项。初始三角形不是已确认的最稳定构型；根据证据与实际需要考虑不同自旋/异构体分支，不把全局最低能量结构当成已知。
- 方法建议针对团簇、阴离子和能量差，说明基组弥散性、收敛与成本考虑；优化和最终能量可以不同方法，同一能量差所用最终协议应可比较。不强制所有体系都用某一泛函。
- 查明所选方法在目标 REST 版本对能量、力、Hessian 的分别支持情况。能算单点不代表能算同方法的解析频率；不支持的导数路线不能通过换名字或静默换方法绕过。
- 缺实际优化结果时只能交付当前具备条件的输入，后续任务明确等待结果坐标和单位，不把初始坐标冒充优化结果。也不能以生成优化卡证明优化已经完成。
- 该需求涉及前置结果或能量组合，应自动保存多步计划，交付当前就绪的输入，不要求用户另说“保存”。

按目标区分的验收分支：

| ID | 用户明确目标 | 任务与公式核对 |
| --- | --- | --- |
| AL3-02 | 只计算电子 VDE | 阴离子目标几何上的阴离子与中性电子能；若目标是优化阴离子构型，先等待其优化结果。不自动加入平衡构型 ZPE 差 |
| AL3-03 | 只计算电子 ADE | 阴离子与中性各自目标平衡几何上的电子能；标明未含 ZPE |
| AL3-04 | 对比振动基态 0–0 ADE | 两个物种各自优化、必要频率/最低点检查和 ZPE 来源、最终电子能及组合；频率和能量的协议与来源分别记录 |
| AL3-05 | 同时比较 ADE 与 VDE | 可以复用阴离子自身几何上的能量，但中性自身几何与中性在阴离子几何上的能量分开，依赖不混用 |
| AL3-06 | 要完整光电子谱 | 解释需要额外电子态/振动态、强度和展宽等谱学处理，具体范围按目标与能力确定；不得把一个能量差或输入卡说成完整谱图 |
| AL3-07 | 只补回阴离子优化结构 | 解锁以该结构为前提的任务；不能因此解锁仍缺中性自身几何的任务 |
| AL3-08 | 回填坐标却没说明结果单位 | 继续等待单位，不继承起始结构单位作为确认 |
| AL3-09 | 要求保存，然后改最终能量方法 | 同组能量协议同步检查、局部修订、旧卡可追溯；已经收到的结果不能无条件沿用到另一方法 |

电子 VDE 应核对 `E(neutral, R_anion) − E(anion, R_anion)`；电子 ADE 应核对 `E(neutral, R_neutral) − E(anion, R_anion)`。振动基态 0–0 ADE 在后一项上加 `ZPE(neutral) − ZPE(anion)`。这些定义可参照 [原始研究中的计算方法说明](https://pmc.ncbi.nlm.nih.gov/articles/PMC9862062/#sec3-ijms-24-01682)。该文献支持定义，不支持对 Al3 的具体泛函、自旋或误差推荐。

实验谱带位置/阈值的赋值应依据具体实验，不把理论量与所有谱峰/首个可见起点无条件等同。当前只准备输入；这些检查验证计划和说明，不要求智能体提前给出数值结果。

| --- | --- | --- |
| MAINT-01 | REST 能力来源 | 每项能力记录目标版本/源码提交、字段与单位、组合限制、来源和测试；README、发布版本和当前 master 不混用 |
| MAINT-02 | 单一参数契约 | Python 科学/接口字段为权威来源，插件 schema 自动生成；维护描述不复制第二套必填规则；契约检查拒绝过期产物 |
| MAINT-03 | 规划规则 | 按物理量、状态和依赖组织通用规则；水与 Al3 是测试案例，不成为硬编码体系特判或固定推荐模板 |
| MAINT-04 | 程序与模型职责 | 模型理解需求、解释取舍和提出建议；程序持有版本、参数状态、能力限制与交付校验。规则若要求拦截，不能仅存在于提示词 |
| MAINT-05 | 确认与证据 | 采用推荐、用户实际确认、证据支撑分别记录；source 声明不冒充可信确认。当前缺口在上线结论中明确评级 |
| MAINT-06 | 结果与结构来源 | 任务记录物种、电荷/自旋、几何来源、单位和所选方法；无结果不解锁，外部结果有清楚来源；输入准备与结果完成分开 |
| MAINT-07 | 新增能力的改动范围 | 能力契约、渲染、独立校验、必要的通用规划规则和对应案例能形成闭环；不依赖多处手工复制字段或全文重写提示词 |
| MAINT-08 | 历史与迁移 | 旧计划/旧卡可读，未知参数不自动变成已确认；历史正文不重写；未来格式拒绝写入；升级有备份、失败可回滚 |
| MAINT-09 | 回归资产 | 固定案例 ID、原始提问、必要的后续用户动作与行为判据；科学结构和依赖是判据，不要求逐字复现回答 |
| MAINT-10 | 泛化检查 | 换物种、电荷、坐标单位和比较目标后仍按实际条件规划；不复用 Al3 的自旋/泛函，不给单原子机械安排分子振动频率 |

REST 能力以 [固定源码与覆盖清单](../../packaging/rest-coverage.md) 为准；README 不是完整清单。新增能力须核对版本、解析代码和真实运行。

## 执行与上线判断

验收分三层保存证据：后端确定性检查；实际宿主工具/schema/文件交付；真实模型多轮对话。源码测试、提示词文本测试、冻结后端检查不能替代真实对话。

每次执行记录 AIFS 提交和包版本、目标 REST 版本、平台、模型及模式、原始用户回合、实际确认事件、工具参数/结果、计划版本与依赖、最终 `.in` 和校验结果。UI 或文件问题记录可复现步骤；密钥等敏感信息不进入报告。

未确认出卡、静默改变单位/方法、几何来源混用、错误分析式被当成已证明、虚构完成计算、丢失保存内容或交付内容不同于校验正文，属于阻止上线的问题。解释质量、重复提问、检索耗时、响应体积和恢复体验按严重程度另行评级。

完整验收后分别报告：阻止上线的缺陷；本次上线范围内的修复项；允许后续迭代的改进；尚未验证的能力/平台/模型。不得把“可生成格式合法输入”当成任务规划与产品可靠性已经验收。
